# Lucky 反向代理配置（用户的实际反代工具）

Lucky 在「Web 服务 → 添加规则 → 子规则」里按**前端地址（域名）**分流。你的公网统一入口是 `:8080`，两个域名走两条子规则。

## 前提

- 后端 API 容器监听 `8789`（用户端）与 `8788`（管理端），宿主端口映射或容器网络可达。
- 域名 `links.example.com` 与 `links-admin.example.com` 都解析到服务器，并都指向 `:8080`。
- HTTPS 证书需覆盖这两个域名（泛域名 `*.example.com` 或两个独立域名），在 Lucky 的 SSL/TLS 里用 ACME 申请。

## 主规则（Web 服务）

- 名称：`durlinks`
- 监听端口：`8080`
- TLS：开启（选已申请的证书）
- 默认子规则：关闭连接（避免裸 IP/未匹配域名误入）

## 子规则 1 — 用户端网页 + API（免登录）

- 服务类型：反向代理
- 前端地址：`links.example.com`
- 后端地址：网页静态站与 API 二选一托管方式：
  - **方式 A（推荐，nginx 容器）**：后端地址填 nginx 容器地址，nginx 按 `/api` 再转 `api:8789`
  - **方式 B**：若 Lucky 直接指 API，则静态站无法托管，网页版需另找地方放
- BasicAuth：关
- 禁用长连接：关（Blazor 可能需要长连接）

## 子规则 2 — 管理端网页 + API（多用户登录）

- 服务类型：反向代理
- 前端地址：`links-admin.example.com`
- 后端地址：同上，指向 nginx 管理站（`/api` 转 `api:8788`）
- BasicAuth：**关**（鉴权由管理网页内的 JWT 登录处理，不在 Lucky 层）
- 禁用长连接：关

## 要点

- 两个域名天然隔离，不存在路径冲突。
- 管理端鉴权在应用层（用户名+密码+MFA），Lucky 只做流量转发。
- 若 Lucky 和后端不在同一主机，后端地址填服务器内网 IP，如 `http://127.0.0.1:8080`（若 nginx 映射到此端口）。

## 验证

1. 浏览器打开 `https://links.example.com` → 看到搜索页，能列出链接。
2. 打开 `https://links-admin.example.com` → 看到管理后台登录页。
3. 用 admin / 初始密码登录，能隐藏/删除、导入、配置 LLM。
